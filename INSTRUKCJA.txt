Sygnał Dnia — poprawka 2.4: niezależne relacje i jedno nazwane źródło

WGRANIE
1. Rozpakuj ZIP.
2. https://github.com/k0fa/sygnal-dnia → Add file → Upload files.
3. Wgraj generator.py, newsroom.py i test_pipeline.py do katalogu głównego.
   Zachowaj dokładne nazwy; zastąp poprzednie pliki.
4. Commit changes.
5. Po zakończeniu uruchomienia wywołanego zmianą kodu wybierz:
   Actions → Generate and publish news → Run workflow → main → Run workflow.
Nie zmieniaj sekretu, modelu, workflow ani historii opublikowanych materiałów.

CO ZMIENIONO
Dossier rozróżnia:
- independent: rzeczywiście niezależne relacje, nadal wymagane dwie grupy wydawców;
- attributed: opis jednego nazwanego sondażu, depeszy lub komunikatu.
  Nie jest on przedstawiany jako niezależnie potwierdzone wydarzenie.

Samo independent=false nie wystarcza do publikacji. Model musi wskazać tryb
attributed, rodzaj materiału i nazwę pracowni/agencji/autora komunikatu,
popartą dokładnym fragmentem pobranego tekstu. Nazwa i dowody są sprawdzane
w kodzie, a ich znaczenie i poprawność dodatkowo przez model w końcowej ocenie.
Gdy pochodzenia nie można ustalić, publikacja nadal jest wstrzymana.

Nazwa pierwotnego źródła musi wystąpić w podsumowaniu i pierwszym akapicie.
Tytuł sondażu musi zawierać słowo „sondaż”. Inne relacje muszą wskazać
nazwę źródła lub formułę „według”. Sprawdzenie semantyczne ocenia atrybucję
twierdzeń i odrzuca sugerowanie niezależnego potwierdzenia przedruków.

W artykule pojawia się nota „Pochodzenie informacji” z przypisami.
Nie sugeruje ona, że pobrano oryginalną depeszę: informuje o opracowaniu
na podstawie wskazanych publikacji.

SONDAŻE
Pracownia badawcza jest wymagana i musi być wskazana w materiale.
Zleceniodawca, termin, próba oraz metoda są podawane z dowodami lub
oznaczone „nie podano w dostępnych materiałach”. Braki nie są uzupełniane
z pamięci modelu. Publikacja wyjaśnia, że sondaż nie jest wynikiem przyszłych wyborów.
Jeśli brak metodologii uniemożliwia rzetelny opis konkretnej tezy, kontrola końcowa
nadal może odrzucić artykuł.

POZOSTAŁE ZASADY
Wybór tematów nadal zaczyna się od grup 2–5 pozycji RSS z co najmniej dwóch
grup wydawców. Po usunięciu mocno powielonych tekstów może pozostać jeden materiał.
Kod dopuszcza wtedy wyłącznie zweryfikowaną relację attributed; pojedynczy tekst
nie przejdzie jako niezależne potwierdzenie.
Minimum 300 słów materiału i 6 udokumentowanych faktów nadal obowiązuje.
Długość 180–300, 300–550 lub 600–1000 słów jest dobierana jak w wersji 2.3.
Maksymalnie 5 wywołań API i 1 artykuł w cyklu.
Tematy wysokiego ryzyka nadal wymagają adekwatnego dokumentu urzędowego
i dodatkowej kontroli. Nie wystarcza samo nazwanie depeszy.

SPRAWDZENIE
53 testy zaliczone lokalnie na Python 3.15, bez pominiętych testów.
Testy obejmują nowe tryby, fałszywą nazwę źródła, fałszywą metodologię,
brak atrybucji, źródło po usunięciu duplikatów, wysokie ryzyko,
zapis artykułów i obecność noty oraz przypisów na stronie HTML.
Testy używają atrap odpowiedzi API, nie klucza użytkownika.
Dotychczasowy workflow używa Python 3.12; wynik jego uruchomienia potwierdzi
działanie w środowisku użytkownika. Nie zmieniono repozytorium zdalnego.
Nie dodano płatnego wyszukiwania ani nowych zależności.
To automatyczna kontrola zgodności z materiałami, nie gwarancja prawdziwości
informacji. Publikacja może zostać wstrzymana.
